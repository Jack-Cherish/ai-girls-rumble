# AI 娘大乱斗 · v8.21 重制源码包

十二位内置斗士可从主菜单选人进入对战，其中包括奶龙与牢大。万局实验室覆盖全部十二位内置斗士。

## 启动

Windows 会优先使用已有的 Node.js 18 或更高版本。缺少可用版本时，双击启动器会从 nodejs.org 下载对应 x64 或 ARM64 的 Node.js 24，核对 SHA-256 后装到当前用户的 `%LOCALAPPDATA%\AI-Girls-Rumble\runtime`，随即启动游戏。首次自动安装需要联网，之后可离线启动。macOS 和 Linux 需预先安装 Node.js 18 或更高版本。

- Windows：双击 `点击开始游戏.cmd`，启动器配置为打开 http://127.0.0.1:4430/ （Windows启动流程未实测）
- macOS / Linux：在本目录运行 `node server.cjs`

保持启动窗口开启。若页面先于服务打开，请等窗口显示地址后刷新。服务正常启动后，同一 Wi-Fi 设备可按窗口列出的局域网地址尝试加入；手机与联机尚未实测。

## 综合对战

在「设置 → 本地 AI」保存模型，打开「综合对战」选人。可以先与对手谈个人协议，或点「跳过谈判，进入拍卖」。每回合的公共规则由双方暗标决定。玩家残血时按 F 发起谈判，履约与背约影响好感、信任。结算同时列出拍卖与履约记录。只想谈判或只想拍卖时，可从各自的主菜单入口进入。

## 规则拍卖

启动本机 Ollama，先在游戏「设置 → 本地 AI」读取并保存模型，再进入「AI 博弈对战」，在选人界面切换为「仅拍卖」。每回合生成三个候选，经本机战斗引擎换边推演后同时公布。无拍卖规则的基准与各候选各测 32 回合，平局按半胜。已保存本地模型时，打开游戏会预生成首轮规则；之后每次揭标会预生成下一回合，前台谈判优先。开拍时按照当时能量和约定做最终推演。没有实际触发、相对基准胜率偏移超过 22 个百分点、明显增加速杀或高血量超时的卡会被替换。保留通过的卡和原推演结果，重试请求只补缺少的张数。拍卖时显示按对手人格生成的锁标台词；模型台词未到时显示角色的默认竞价台词。结果是小样本估计。模型或推演失败时可重试或退出，期间战斗冻结。

双方各有 100 枚本场筹码，双方先各选一项擂台技能并暗标下注。赢家支付报价，所选技能当回合对双方生效。玩家也可以放弃竞拍并保留筹码，此时对手按其锁定的报价成交。平价时按本轮公示的优先权，首次随机，同价结算后交换。场地规则双方通用，回合结束到期；平局加赛也共用剩余筹码。新比赛双方回到 100 枚。原有 AI 谈判在「AI 博弈」入口。「综合对战」串联赛前谈判、回合拍卖和残血谈判。拍卖推演使用当前回合仍有效的私人协议。

## 博弈试玩
   
玩家可以先问“能不能轻点打？”。对手会结合自己的性格追问，玩家说清期限和幅度后才推演。比如“第一回合你打我只造成一半伤害”可在签约后实际生效，伤害逐击取整，原本会扣血的每击至少 1 点，护盾仍可完全挡伤。推演成功时展示实测胜率；本地模型模式下若推演暂不可用，会标明缺少数据并由对手根据条款评估。

1. 在主菜单选择「AI 博弈」，锁定双方角色，再进入赛前谈判。
2. 在主菜单「设置 → 本地 AI」读取本机 Ollama 模型，选中后自动保存。点击「测试连接」会实际发送一条赛前提议，显示模型给出的协议或答复。首次加载最多等待 150 秒。谈判出错时会显示原因，保留原提议供重试。选用规则陪练时，谈判画面提供预设提议。
3. 本机模型接收自然语言条件，可以同意、追问、还价或拒绝。每份协议可组合停手、借技能、禁用技能、先攻、减伤、走位速度和技能恢复速度，各自指定回合或整场。例：“开场等我五秒，我先出手你就还手，二技能借我一次，这场都能用。” 对手还能移动和防御。借招占用接招方原按键，沿用冷却和能量规则；放出才扣次数，出借方保留自己的招式。逐条核对后点击「成交，开战」，也可以改口或按普通规则开战。再来一局会重新谈判。
   
   对手有好胜、慷慨和冒险三项属性，好感和信任按角色保存在当前浏览器，供档案与离线评估使用。赛前的每份候选协议都和普通规则使用相同的 32 个种子，在后台按双方实际技能和当前难度模拟完整比赛。双方由电脑操作，推演跳过残血对话。展开「对手档案与胜率推演」可查看胜平负与关系。离线陪练会按性格与关系确定愿让的胜率差；本地模型还可以为了陪练、人情等理由作出不同选择。包括整场无条件停手在内的受支持协议都可以签。
4. AI 博弈中，自己血量降到 25% 或更低时按 F 或点「发起谈判」。对手残血时也可以主动开价，每回合双方共用一次机会。双方进入谈判后暂停计时，签约或离开就回到当前战斗。
5. 本地模型会参考角色性格、好感、信任、双方血量、能量、旧约和近期报价，自行组合借招、停手、先攻、禁用技能、减伤、走位速度和技能冷却恢复速度。你可以直接改价、追问或拒绝。规则陪练可展开「自拟交换条件」，自行组合最多六条。签约前以屏幕上的具体条款为准。
6. 战斗中答应停手后仍然可以走位、防御、跳跃和闪避。提前打出普攻、技能，或使出自己答应禁用的招式，会实际出招并记为背约。冷却、能量不足等导致的空按不算。若条款写明「对方先出招就可以还手」，该条件生效后的还击合规。走位速度、伤害倍率等持续效果也可用「背约」按钮撤销。每份协议的个人承诺只结算一次，守约好感 +3、信任 +6，背约好感 −10、信任 −18（0 到 100）。
7. 结算页可回看本场履约记录。旧交手以及好感、信任仍保留在对手档案。每次打开新的谈判窗口，本机模型按初次见面回应，只保留本窗口的上下文；离线陪练的让步参考仍受关系数值影响。上一场的约定随比赛结束。

## 规则

- 三局两胜，每局 60 秒，时间到按剩余体力判定。
- 同一套连击中伤害逐次递减；连续挨打 6 下会被强制击倒，起身有短暂无敌。
- 防御只挡正面，防御条耗尽会破防。护盾期间出普攻会收盾。
- 技能命中攒奥义点，满 4 点可放奥义。奥义点跨回合保留。

十个角色使用统一人格档案，GPT 与 DeepSeek 按确认的设定交换。好胜/慷慨/冒险同时用于离线让步参考值及本地模型的理解、决定、残血谈判。对手档案显示人格说明，离线对白使用逐角色台词，本地模型自行生成对白。好感、信任存档与 32 场胜率推演保留。

## 万局实验室

1. 启动此目录下的游戏，进入「万局实验室」。点击「开始实验 · NSGA-II」即可在本机进行万局调参，无需启动 Ollama。通过验证的配置可手动应用到新开的本机比赛。AI 谈判仍可在本版本设置中单独配置本地模型。
2. 想先熟悉界面可点「试跑 144 场」。每个有序对阵各打一场，可看回放和导出，但样本量不足以决定平衡调整。
3. 点「开始实验」。程序发起原版基准测试，本机工作线程并行运行游戏的固定步长战斗引擎。每批 14,400 **场三局两胜比赛**，包括十二名内置角色的 144 个有序对阵，每格 100 场。使用普通难度、原版装备、无谈判协议。相同实验种子和代码版本可重跑，调换座位共享种子。局/秒按实际耗时计算。保留浏览器标签页，点「停止」可取消实验。
4. 点热力图中的对阵，选场次看实际输入重演，可逐帧或慢放。「试着防御」把受击方在第一次命中后的输入替换为持续防御。它只检验这一种操作。「原版对比」使用同一串输入检验参数变化，正式胜率比较则让两边的 CPU 自行决策。
5. NSGA-II 每代最多产生 12 个不同子代，种群最多保留 12 个个体。初代对原版做稀疏变异，后续按非支配等级与拥挤距离进行锦标赛选择，逐参数交叉继承，再变异 1 或 2 项。亲代与实测子代合并筛选，最后一层按拥挤距离截取。界面显示来源、亲代编号及新增变异，完整配置写入批次 JSON。保留页面可停止并续跑。
6. 每份配置先用固定输入检查三个距离的出招、持续进攻、防守、追击和续航，再用同批种子对照。结果表同时显示回合时长、速杀、高血量超时、长时间无掉血的超时、单招伤害、连续受击和角色胜率。平衡目标为回合时长中位数 25–40 秒、8 秒内结束低于 1%、两类僵局各低于 2%、单次出招满血伤害 0 场、无奥义连续伤害不超过 35%、非镜像整体胜率 45%–55%，镜像 1P 得分率 45%–55%。这些指标描述当前模拟策略下的观测结果，玩家仍可用不同打法发现问题。
7. 候选配置达标后，程序会发起两批独立种子验证。换边合计后同一对阵在两批中都向同一方偏过 70:30，也会拦下这份配置。验证失败后，将保留路线切换到失败种子比较并继续搜索，通过后回查原始种子并换新种子再次验证。「应用通过验证的配置」影响后续新开的本机对局，跳过工坊编辑过的角色。可点「恢复原版参数」。局域网对战使用联机端原参数。
8. 在结果页切换原版、当前最佳和最近完成的批次并导出 PNG 成绩卡或 JSON。JSON 包含本次实验的遗传搜索记录、每批耗时和汇总、当前所选批次的逐场种子与结果。关页前请导出需保留的数据。


## 导入以前的实验参数

在「设置 → 万局平衡参数」选择旧实验室的实验数据 JSON。如果文件含通过验证的配置，优先显示该配置；也可选择报告中当时展示的实验批次，查看每个角色技能参数的前后值，再点「应用到新对局」。仅保存角色参数，无需重新跑实验。也支持新版实验室「导出参数 JSON」生成的小文件，PNG 成绩卡不含完整配置。应用范围与实验室的应用按钮相同。可随时恢复原版。

### 候选参数的实际重算场数

NSGA-II 评估每个候选时，先比较其与同种子、同规模的完整历史批次的角色装备参数。亲代、另一交叉亲代、本代已经评估的候选和保留批次都可作为参照。选择可沿用场数最多的一批，平手时优先当前亲代。复用时还逐场核对选手、座位、编号和随机种子。

「本批结果」会显示参照批次、实际有变化的角色、实际模拟场数及沿用场数。十二名角色均匀对阵 14,400 场时，相对亲代只改一个角色，至多重新模拟 2,300 场。进度条中的“已统计”包含了沿用结果，旁边的“场实算/秒”只计算新模拟的场次。首次基准和独立验证仍使用完整批次。

## CPU 与 GPU 同队列滚动计算

解压到独立目录，关闭旧启动窗口，双击「点击开始游戏.cmd」，在万局实验室点击「开始实验」。首次用另一组种子对照两端的 20 场结果。联合模式下，CPU 每个工作线程算完一场就交回；GPU 对局槽位可选 256、512、768、1024，默认 256。浏览器从同一队列预取一部分任务到显卡，在显卡上排队。只要队列还有任务，空槽位就直接领取下一场。每推进 384 个模拟帧检查一次完成记录，集中汇报并补充待算任务。实际同时工作的槽位数取决于待算场次和显卡调度。实验 JSON 包含每批所选档位、两端完成数及复用场数。

显卡需支持双精度 OpenCL，并从 Windows 本机启动器页面访问。显卡不可用、核验失败或批次中途报错时显示具体原因，剩余场次由 CPU 接手。独立种子最终验证使用 CPU 原引擎。补位和通信都有开销，比较两版时用相同种子、线程数与搜索代数记录实际耗时。
